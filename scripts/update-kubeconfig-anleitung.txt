Das Script update-kubeconfig.sh wird auf k8s-mgmt-10 ausgeführt und erledigt folgendes automatisch:
1. Prüft welche kubeconfig-Dateien im Repo-Root vorhanden sind:

kubeconfig-dev.yaml → K3s DEV (k8s-dev-21/22/23)
kubeconfig-dev-microk8s.yaml → MicroK8s DEV (k8s-dev-01/02/03)
kubeconfig-test.yaml → K3s TEST
kubeconfig-prod.yaml → K3s PROD

Fehlende Dateien werden einfach übersprungen.
2. Benennt die Context-Namen um:

K3s-Dateien: default → k8s-dev / k8s-test / k8s-prod
MicroK8s-Datei: microk8s-cluster, microk8s, admin → k8s-dev-microk8s
MicroK8s: Server-URL 127.0.0.1:16443 → 192.168.180.11:16443

3. Mergt alle gefundenen Dateien zu ~/.kube/config (mit Backup der alten config)
4. Optional mit --scp: Verteilt die fertige config per scp auf andere Hosts (MacMini, MacBook, Windows) — sobald du die IPs oben im Script einträgst.

Typischer Workflow bei Cluster-Rebuild oder neuer kubeconfig:
bash# Neue kubeconfig vom Cluster holen, z.B. MicroK8s:
ssh admin-ubuntu@192.168.180.11 "sudo microk8s config" > ~/git/eneg-k8s-infrastructure-v2/kubeconfig-dev-microk8s.yaml

# Script ausführen:
cd ~/git/eneg-k8s-infrastructure-v2
./scripts/update-kubeconfig.sh
